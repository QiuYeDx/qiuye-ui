# HoneycombView · Apple Watch 风格蜂窝列表

## 目标

复刻 Apple Watch 主屏的蜂窝（App Cloud）视图：圆形图标按六边形密排，靠近视口边缘的图标连续缩小并向内收拢，整体像贴在一块球面上；拖动跟手、松手带惯性、碰到边界有橡皮筋回弹，任何时刻都可以再次抓住。

两种模式：

- `free`：watchOS 9 及以前的「蜂窝」视图，四个方向都能拖动，图标从中心按螺旋一圈圈向外排列。
- `vertical`：watchOS 10 起的「网格」视图，只能上下滚动，窄行与宽行交替（首行 3 个，之后 4 / 3 交替），正中的图标最大、向外逐渐变小，顶部和底部缩成小圆点。

名称为 HoneycombView，registry id 为 `honeycomb-view`，分类「内容与媒体」。

## API

```tsx
<HoneycombView
  items={apps}
  getItemKey={(app) => app.id}
  getItemLabel={(app) => app.name}
  renderItem={(app) => <AppIcon app={app} />}
  onItemSelect={(app, index, element) => open(app, element)}
  mode="free"                 // "free" | "vertical"
  itemSize={60}               // 图标直径（px）
  gap={10}                    // 相邻图标间距（px）
  className="h-[360px] w-[300px] rounded-[48px] bg-black"
/>
```

| 属性 | 说明 |
| --- | --- |
| `items` / `renderItem` | 数据与图标渲染。图标内容按 `itemSize` 设计，缩放由组件统一处理；`renderItem` 返回纯视觉内容，不要再嵌套按钮。 |
| `getItemKey` / `getItemLabel` | React key 与每个图标的无障碍名称。 |
| `onItemSelect` | 点击、回车或空格选中。第三个参数是图标元素，便于调用方从图标位置做打开动画。拖动后的松手不会触发。 |
| `mode` | `free`（默认）或 `vertical`。 |
| `layout` | 仅 `free`：`spiral`（默认，从中心一圈圈向外）或 `grid`（宽窄行交替的矩形蜂窝）。`vertical` 固定为 `grid`。 |
| `columns` | 宽行的列数，窄行为 `columns - 1`。`vertical` 默认取视口放得下的最大列数，并微调列距铺满宽度；`free` + `grid` 默认取接近正方形的列数。 |
| `itemSize` / `gap` | 图标直径与间距，默认 60 / 10。 |
| `edgeWidth` | 边缘缩放带的宽度（px），默认 `0.65 × itemSize`：图标中心距视口边缘小于该值时开始缩小，最终缩成贴着边缘内侧的小圆点。越宽，越早开始缩小。 |
| `cornerRadius` | 视口圆角（px），让缩放带沿圆角屏幕弯曲：角落的图标比边中点更早开始缩小。默认读取根节点的 `border-radius`；圆角由外层容器裁切时需要手动传入。 |
| `curvature` | 球面感（0–0.9）：图标从视口中心向外整体逐渐缩小、间距随之收紧的程度。默认 0.4（按 watchOS 10 网格拟合）。 |
| `snap` | 松手后吸附：`free` 让最近的图标停在正中，`vertical` 让某一行停在顶端。默认开启。 |
| `itemClassName` | 每个图标按钮的样式（默认圆形焦点框；图标形状由 `renderItem` 决定）。 |

根节点转发 ref，透传其余 `div` 属性；`aria-label` 默认「应用列表」。

## 设计细节

### 1. 布局（虚拟坐标）

图标中心距 `d = itemSize + gap`。六边形密排：同一行间距 `d`，行距 `d·√3/2`，相邻行错开 `d/2`。

- 螺旋：轴向坐标 `(q, r)` 从中心开始，第 k 圈 6k 个，按 redblobgames 的环形遍历生成；第 0 个数据在正中。屏幕坐标 `x = d·(q + r/2)`、`y = d·√3/2·r`。
- 网格：宽行 `columns` 个、窄行 `columns - 1` 个，各行水平居中，于是窄行的图标正好落在宽行两个图标之间；左右边界是直的。

### 2. 边缘缩放（核心）

把视口分成两块：中心的满尺寸区域（视口每边向内收 `edgeWidth`，圆角与视口圆角同心）和外圈的缩放带。对每个图标：

1. 虚拟坐标加上平移量，得到相对视口中心的点 `p`。
2. 求 `p` 到满尺寸区域的最近点 `b` 和越界距离 `u = |p - b|`（区域内 `u = 0`）。圆角矩形的最近点：先把矩形收缩圆角半径得到核心矩形，`p` 夹到核心矩形得到 `q`，若 `|p - q|` 大于圆角半径，则 `b = q + 单位向量 · 圆角半径`。
3. 缩放写成屏幕位置的函数：`v` 为图标在缩放带中走过的距离，`x = v / L`（`L = 0.82·edgeWidth`，即渐近线距视口边缘 `0.18·edgeWidth`），`s(x)` 前半段二次缓入、后半段线性降到 0。参数按 Apple Watch 真机截图拟合。
4. 屏幕位置满足 `dv/du = s(v)`：空间压缩多少，图标就缩小多少，相邻图标沿径向的间隙随之收紧，不会出现小图标之间留着满尺寸间隙的空洞。越界很远的图标趋近渐近线、缩成贴着边缘内侧的小圆点，不会被视口边缘裁掉。该映射在模块加载时用 RK2 积分成查找表，每帧插值。

`vertical` 模式下缩放带只作用于上下两端：满尺寸区域的半宽取 `max(视口半宽 - edgeWidth, 内容半宽)`；水平方向的层次来自球面感（`curvature`，见文末第四轮），正中的图标最大、向外逐渐变小。最外两列在上下两端随圆角更早缩小，呈现圆角屏幕的轮廓。

缩放小于 0.24 时逐渐淡出、0.16 以下消失（完全淡出后 `visibility: hidden`），边缘只留一圈小圆点；小于 0.5 时关闭命中，太小的图标不响应点击。

### 3. 平移边界

平移量的允许范围让最外圈图标刚好能被拖进满尺寸区域的边缘：每个轴 `[区域半宽 - 内容最大值, -区域半宽 - 内容最小值]`；内容比区域小时该轴固定居中。初始位置：`free` 让第 0 个图标在正中，`vertical` 停在顶部。

### 4. 手势与物理

不用浏览器滚动，也不用 Motion 的 `drag`：平移量是两个 MotionValue（X / Y 各一个，分别动画），自己处理 Pointer Events，这样两种模式、拖动、惯性、橡皮筋与吸附共用一套物理。

| 环节 | 做法 |
| --- | --- |
| 按下 | `setPointerCapture`，立即停止正在进行的惯性或回弹，从当前屏幕上的值继续（可中途抓住）。按到图标时图标立刻缩小到 0.92（按下即反馈）。 |
| 拖动 | 移动超过 6px 才认定为拖动并取消图标按压；之后 1:1 跟手，保留抓取偏移。`vertical` 只取纵向分量。 |
| 越界 | 橡皮筋 `r(o) = o·D·c / (D + c·o)`（`c = 0.55`，`D` 为视口尺寸），越拉越沉。中途抓住越界状态时先反解橡皮筋，避免跳变。 |
| 速度 | 记录最近 100ms 的指针采样，松手前 50ms 内没有移动则视为静止松手（速度为 0）。 |
| 惯性 | Motion `inertia`：`power` 与 `timeConstant` 由 UIScrollView 的减速率 0.998 推出（`timeConstant = -1 / ln(0.998) ≈ 500ms`，`power ≈ 0.5`），`min / max` 为平移边界，越界时由弹簧回弹。 |
| 吸附 | 开启 `snap` 时按 Apple 的投影公式 `v / 1000 · d / (1 - d)` 预估落点，选最近的图标（或行）作为目标，再用临界阻尼附近的弹簧（`bounce 0.12`）带着松手速度过去。 |
| 滚轮 / 触控板 | 非 passive 的 `wheel` 监听，累加到目标值后用短弹簧跟随（Windows 滚轮逐格也平滑）；目标值夹在边界内。两个方向都已到边界时不 `preventDefault`，让页面继续滚动。 |
| 点击 | 拖动过的那次松手吞掉 `click`。 |

### 5. 入场

挂载时图标从中心向外依次展开：一个 0 → 1 的进度值，每个图标按到中心的距离延迟，位置从 55% 处展开、缩放与透明度同步升起（约 0.7s）。这是 watchOS 从表盘回到主屏时的「散开」。

### 6. 渲染与性能

- 图标数量常在 30–100 个，每帧都要重算位置与缩放。不走 React 渲染：订阅平移与入场三个 MotionValue，用 Motion 的 `frame.render` 每帧最多算一次，直接写每个图标的 `transform` 和 `opacity`。
- 图标绝对定位在视口中心，只改 `translate3d + scale`，加 `will-change: transform`，滚动全程只走合成。每帧改写的是无类名的定位 div，可聚焦的 button 在其内部；内层不依赖外层样式；只写发生变化的值（见文末「性能与边缘还原」）。
- 视口尺寸用 ResizeObserver 记录；尺寸、数据或参数变化时重新布局，并把平移量夹回新边界。
- 首帧在 layout effect 里同步绘制；服务端渲染的 HTML 中图标先 `opacity: 0`，避免水合前堆在一角。

### 7. 无障碍

- 根节点 `role="group"` + `aria-label`；每个图标是 `button`（有 `onItemSelect` 时）并带 `aria-label`。
- Tab 依次聚焦；方向键在六个邻居中按方向选最接近的一个，聚焦后平移让它进入满尺寸区域。
- 视口 `overflow: hidden`，聚焦时浏览器可能偷偷滚动容器，`scroll` 事件中归零。
- 减少动态效果：不做入场展开，吸附与回弹不带过冲；拖动仍然 1:1 跟手（直接操作不属于前庭刺激）。

## 不做（第一版）

- 数字表冠缩放（整体放大缩小、放大到中心图标后打开）。设计上预留：所有几何都基于 `d` 与平移量，加一个缩放 MotionValue 即可；可以映射到 Ctrl / ⌘ + 滚轮和双指捏合。
- 拖动重新排列图标、命令式 API（如 `scrollToItem`）。
- 打开应用的放大转场：组件只把图标元素交给 `onItemSelect`，Demo 中演示一种做法。

## 验收

- 两种模式：拖动跟手、松手惯性、越界橡皮筋与回弹、中途抓住无跳变；`vertical` 只能纵向移动。
- 边缘图标连续缩小并向内收拢，相邻图标不重叠、无空洞；`vertical` 各列保持满尺寸。
- 点击选中、拖动后不误触；键盘 Tab 与方向键可用，聚焦图标会被移入视野。
- 滚轮在桌面平滑滚动，到边界后页面可继续滚动。
- 浅色 / 深色主题、390px 与桌面宽度、减少动态效果。
- `pnpm lint`、`pnpm build`、registry 内容与源码一致。

## 实施与验证记录（2026-10-18）

与设计相比的调整：

- **边缘缩放不再趋近 0**：最初按 `o' = W·tanh(o/W)` 把所有越界图标都压进视口，结果是满尺寸图标外面一圈很快变成一排小圆点，边缘的小点之间沿边方向仍隔着满尺寸间距，显得稀疏。改为 `o' = m·o + (1 - m)·W·tanh(o/W)`，缩放 `m + (1 - m)·sech²(o/W)`（`m = minScale`，默认 0.3）：边缘图标缩到一半左右、被视口边缘裁掉一部分，越界更远的图标以缩小后的尺寸慢慢滑出视口，更接近 Apple Watch。缩放不会过小，原先「缩放小于 0.3 时淡出」的处理随之去掉，只保留缩放小于 0.45 时关闭命中。（第二轮对照真机截图后改回渐近到小圆点的映射，见下文「边缘缩放」。）
- **free 模式平移边界**：最外圈图标能拖进满尺寸区域边缘时，视口另一侧会留出近一个图标宽的空白。free 模式改为最外圈最远到达缩放带中段（`FREE_REACH = 0.5`）；vertical 模式仍让首行停在满尺寸区域顶端。
- **inertia 的目标值**：Motion 在起止关键帧相同时会跳过动画（`canAnimate` 只对 spring 和生成器函数放行），而 inertia 只用起点和速度计算落点。松手时若传当前值作为目标，惯性与越界回弹都不会发生；改为传一个不同的占位目标。
- **指针捕获**：确认拖动后才 `setPointerCapture`（否则 click 会落到根节点），并用 `try/catch` 包裹，指针已失效时继续跟随。

验证（Playwright Chromium 1280×900 与 390×844 触屏，开发服务器）：

- 慢拖后静止松手停在原地；甩动后继续滑行，到边界回弹（水平方向 145 → 115，纵向继续滑到边界），全程约 0.9s 静止；向右越界拖 400px 后松手回到边界。
- 打开吸附后甩动，落点为离投影最近的图标位置（受边界约束时停在边界）。
- 点击图标打开 Demo 的应用转场，轻点返回；拖动 30px 后松手不会打开。
- 键盘聚焦第一个图标后按三次 → 焦点按六边形邻居移动；vertical 模式滚轮下滚 240px 平滑跟随。
- vertical 模式各列满尺寸，上下两端缩小，最外两列在角落更早缩小；任意尺寸画布（1169×420）中整片蜂窝只有上下两端缩小。
- 390px 宽度下表盘等比缩小，页面无横向溢出，触屏点按打开正常。
- `pnpm lint`、`tsc --noEmit`、`pnpm build`（25 个静态页面，含 `/components/honeycomb-view`）通过；`pnpm update-registry` 只更新了 `honeycomb-view` 一项。

未覆盖：真实 iPhone / Apple 触控板的手感与帧率、系统级减少动态效果的实机切换。

## 性能与边缘还原（2026-10-18，第二轮）

反馈：① 鼠标长按来回拖动会越来越卡，CPU 占用接近 100%，过一阵突然变流畅又重新变卡；② 对照 Apple Watch 真机截图，靠近屏幕边缘的图标应缩得很小，当前边缘图标仍然很大。

### 性能

在本机用有界面的 Chromium（120Hz）按住鼠标连续拖动，CDP 指标与 trace：渲染主线程约 87% 忙碌；每帧主线程 6.7ms（预算 8.3ms），其中样式重算 3.4ms、Layerize 2.4ms。主线程已贴着预算，真实鼠标的输入与 GC 一叠加就掉帧，与反馈中的锯齿曲线一致。逐项对照（同一页面插入 51 个测试元素，每帧改 transform）：

| 写法 | 每帧样式重算 | 重算元素数 |
| --- | --- | --- |
| 原实现（button + 类名，内层 `rounded-[inherit]`） | 3.09ms | 102 |
| 无类名的 div，内层不依赖外层样式 | 0.28ms | 51 |
| 外层换成 button（其余相同） | 1.34ms | 51 |
| 放进 Shadow DOM | 0.21ms | 51 |

结论与改动：

- **内层依赖外层样式**：内层 `rounded-[inherit]` 让每次外层 transform 变化都连带对内容做完整的样式重算（行内样式变化不命中匹配缓存，每个元素要对整站样式表重新级联，约 30µs）。去掉内层的 `inherit` 与裁切，图标形状交给 `renderItem`。
- **每帧移动的元素用 div**：button 带表单控件的 UA 样式，重算约贵 4 倍。结构改为「定位用的无类名 div（每帧写 transform）> 可聚焦的 button（按压缩放、焦点框）> 内容」。Shadow DOM 只再省 0.07ms，不值得引入。
- **只写变化的值**：按元素缓存上次写入的 transform / opacity / pointer-events（坐标保留 2 位、缩放 4 位小数），值不变不写；完全淡出的图标设为 `visibility: hidden` 并跳过它的 transform。方向键聚焦到隐藏图标时先取消隐藏再聚焦，随后平移进视野。
- **保留 `will-change: transform`**：去掉后每帧重绘图标内容，帧率掉到 60fps 左右。
- 剩余的 Layerize（约 1.7ms）与页面整体复杂度成正比：同样的 51 个图层放在空白页只要 0.07ms，组件侧无法再降。

复测（同一条件）：每帧样式重算 3.36ms → 0.38ms，主线程每帧 6.7ms → 3.6ms；连续拖动 90s 主线程约 40% 忙碌，帧间隔 p95 8.5ms，没有随时间上升。

排查中的一个干扰：用 Playwright 的 `page.mouse` 按住移动时，它的拖放拦截（`crDragDrop`）每次移动都会增删监听器，耗时随时间增长，看起来像组件越拖越慢；改用 CDP `Input.dispatchMouseEvent` 后消失。本机未能复现「随时间越来越卡」，修复针对的是主线程饱和这一根因，需要在原环境复测确认。

### 边缘缩放

按真机截图（图标直径 S）测量：距边缘约 0.7S 的图标缩放约 0.8–0.86，约 0.25S 处约 0.1，最外一圈是贴着边缘内侧的小圆点，不会被屏幕边缘裁掉；缩放大致随屏幕上到边缘的距离线性变化。据此重做映射：

- 缩放写成屏幕位置的函数 `s(x)`（x 为图标中心在缩放带中走过的比例，0 为满尺寸区域边缘，1 为距视口边缘 `0.18·edgeWidth` 的渐近线）：前半段二次缓入，后半段线性降到 0。
- 屏幕位置满足 `dv/du = s(v)`（u 为虚拟坐标的越界距离），空间压缩多少图标就缩小多少，径向间隙随之收紧。模块加载时用 RK2 积分出 512 段查找表，每帧插值。
- 缩放小于 0.1 时淡出，渐近线上叠在一起的小圆点不会糊成一圈；缩放小于 0.5 的图标不响应点击。
- `edgeWidth` 默认改为 `itemSize`；`edgeRadius`、`minScale` 去掉，改为 `cornerRadius`（视口圆角，默认读根节点 `border-radius`），满尺寸区域与视口圆角同心。
- free 模式平移边界改为最外圈最远拖进缩放带 30%（缩放约 0.8）。

验证：表盘、上下滚动与大画布截图中，满尺寸图标外依次是约 0.9、0.4 的图标和边缘小圆点；拖动、甩动、越界回弹、吸附、点击与拖动区分、方向键（可一路走到最外圈）、390px 宽度均正常。

## 层级与参数调试（2026-10-18，第三轮）

反馈：① 演示缺少可以手动调参的示例；② 重叠时靠左（DOM 中靠后）的小图标盖住了右侧的大图标，视觉上应是大的盖住小的、中间的盖住更靠近边缘的。

- **层级**：图标按 DOM 顺序绘制，螺旋排布中外圈排在后面，于是边缘的小图标叠在内侧大图标上。绘制时按缩放写 `z-index`（`round(scale × 40)`，量化成整数档位，缩放细微变化不改写；与其余样式一样按元素缓存、不变不写）。根节点的 `contain: paint` 已建立层叠上下文，层级不会泄漏到页面。
- **参数调试卡片**：可调 `edgeWidth`、`itemSize`、`gap`、视口宽高与圆角、图标数量、模式、排布与吸附；可叠加显示满尺寸区域边界（白色虚线）与小圆点渐近线（蓝色虚线）；「查看源码」按当前参数生成用法，「重置」恢复默认。

验证（Playwright Chromium，参数调试卡片，默认参数下 14 次不同方向的拖动）：每次停下后找出所有成对重叠的可见图标，在重叠区域中点 `elementFromPoint`。共 32 对重叠，命中的都是较大的图标；这 32 对按 DOM 顺序绘制时全部是较小的在上（修复前的表现）。调大 `edgeWidth`、调小 `gap` 后界面与生成的代码同步更新，无报错。

## 默认吸附、触屏拖动与网格层次（2026-10-18，第四轮）

反馈：① 默认开启松手吸附；② iPhone 上从图标位置开始拖动只能移动一下就断开，只有从黑色空白处开始才能一直拖；③ 对照 watchOS 10 网格视图真机截图：首行是 3 个而不是 4 个，图标大小有层次，不是一律满尺寸。

**触屏拖动中断**：用 CDP `Input.dispatchTouchEvent` 在 Chromium 触屏模拟中复现，从图标上开始拖动时平移停在第一步（8px），从空白处开始则一直跟随。事件记录为 `gotpointercapture@path → lostpointercapture@path → gotpointercapture@root`：触屏按下时浏览器把指针隐式捕获到手指下的元素（图标里的 svg path），拖动开始后改由根节点捕获，原元素的 `lostpointercapture` 冒泡到根节点，被当成拖动结束。鼠标没有隐式捕获，所以桌面端没有暴露。修复：只处理根节点自身的 `lostpointercapture`（`event.target === event.currentTarget`）。另外按下后在非 passive 的 `touchmove` 中 `preventDefault`，并关闭 iOS 长按菜单（`-webkit-touch-callout: none`），避免系统接管手势。复测：从图标上开始的 10 步拖动逐步跟随到 80px。

**默认吸附**：`snap` 默认改为 `true`，Demo 与参数调试同步。

**网格层次**：按截图测量（图标直径约 100px，视口 416×500）：正中的图标最大；到中心的归一化椭圆距离 ρ（视口边缘为 1）约 0.5 处缩放 0.85–0.88，约 0.75 处约 0.76，约 0.85–0.9 处约 0.62–0.68；越往外间距越紧。新增 `curvature`（球面感）：

- 缩放 `1 - k·ρ^1.5`，位置取它沿径向的积分（`ρ - k·ρ^2.5 / 2.5`），间距随图标一起收紧；ρ > 1 后保持 `1 - k`，再交给边缘缩放带。`k` 默认 vertical 0.4、free 0（watchOS 蜂窝视图截图中中心区域等大）。
- 平移边界、vertical 首行停靠位置、吸附目标与键盘聚焦范围都按屏幕目标位置反算回虚拟坐标（二分求反函数），首行仍停在满尺寸区域顶端。
- vertical 模式改为从窄行开始（首行 `columns - 1` 个）。
- 参数调试卡片新增「球面感」滑块。

验证：vertical 模式截图中首行 3 个，正中图标 1.0、相邻约 0.85–0.9、外侧列与上下两行更小，边缘为小圆点；三次不同方向拖动松手后都有一行停在满尺寸区域顶端（偏差 ≤ 1px，为包围盒取整）。free 模式不受影响；触屏、吸附、方向键、点击与拖动区分、层级（29 对重叠均为大的在上）、390px 宽度回归通过。

## 网格模式铺满视口（2026-10-18，第五轮）

反馈：上下滚动模式截图左右和上方的黑边太宽。对照 watchOS 10 网格截图（图标直径 S）：最外列外沿距屏幕边缘约 0.19S，首行顶边距顶端约 0.3S；当前约 0.55S 与 0.7S。原因：

- 列距固定为 `itemSize + gap`，4 列只占 270 / 300px；球面感又让外侧列向内收、变小，空白更宽。
- 首行按中心停在满尺寸区域顶端，没有考虑它已经缩小，顶边离屏幕边缘很远。
- 真机网格是标准蜂窝（列距 / 行距 ≈ 1.15），靠更多的列与外侧缩小铺满宽度，并没有拉开列距。首行中心约在 0.65S 处、缩放约 0.72，几乎只来自球面感；沿用 free 模式按截图拟合的 `edgeWidth = S` 会让首行一往上推就缩成小点。

先试过按比例拉开列距（上限 1.6 倍），中间显得稀疏，首行被推进缩放带缩成小点，已撤回。最终做法（仅 vertical 模式）：

- **列数**：取最外列「屏幕上的外沿」（计入球面感的位置收缩与缩小）不超过 `视口半宽 - 0.18S` 的最大列数；越往外图标越小，能比按满尺寸计算多放一列。再在 0.9–1.1 倍内微调列距，让外沿正好停在 0.18S 处，保持蜂窝比例。
- **首行停靠**：从中心往上逐像素找第一个「屏幕上的顶边」到达距顶端 0.28S 的位置作为平移边界与吸附基准（底端对称）。
- **缩放带**：vertical 默认 `edgeWidth = 0.65 × itemSize`。
- **Demo**：上下滚动模式的表盘按真机比例用 72px 图标（视口宽度约为图标直径的 4 倍），得到首行 3 个、4 / 3 交替；参数调试中仍按滑块取值。

验证：上下滚动截图中首行 3 个，正中图标最大、向外逐渐变小，最外列外沿距边缘约 16px（0.22S），首行顶边距顶端约 29px；从窄行吸附到顶端时中线图标顶边与目标相差 0.3px。触屏拖动、方向键、点击与拖动区分、层级（29 对重叠均为大的在上）、390px 宽度回归通过。

## 自由拖动模式与网格模式统一（2026-10-18，第六轮）

反馈：自由拖动模式也要做与上下滚动模式相同的优化，两种模式的呈现与感觉保持一致。此前 free 模式按 watchOS 蜂窝视图截图保留了「中心等大 + 宽缩放带」，与网格模式的层次感不一致。改动：

- **默认值统一**：`curvature` 默认 0.4、`edgeWidth` 默认 `0.65 × itemSize`，两种模式相同；正中的图标最大、向外逐渐变小，缩放带只把最外一圈压成贴边的小圆点。
- **平移边界统一**：free 模式不再用「最外圈拖进缩放带 30%」，改为与网格首行相同的规则：沿各轴从中心向外，找第一个屏幕上的外沿到达距视口边缘 `0.18 × itemSize`（水平）/ `0.28 × itemSize`（垂直）的位置，拖到边界时最外一圈正好铺到边缘。
- **Demo 尺寸统一**：表盘两种模式都用 72px 图标（视口宽度约为图标直径的 4 倍），首页 / 详情页小表盘按同一比例用 53px；参数调试两种模式的默认值相同。

验证：自由拖动截图与上下滚动截图层次一致（正中最大、外圈渐小、边缘小圆点、边距紧凑）；参数调试与主屏示例两种模式下 51 个图标逐一相同；触屏从图标开始拖动、吸附、方向键、点击与拖动区分、层级、390px 宽度、首页三种宽度回归通过。

## 边缘小圆点收敛（2026-10-18，第七轮）

反馈：自由拖动模式边缘残留的小元素太多，消失得慢，有密集恐惧感，不够简洁。

统计默认视图中可见图标的缩放分布：free 模式有 21 个小于 0.25（其中 13 个小于 0.12，是挤在渐近线上的第二层细小图标），vertical 模式只有 3 个。free 的螺旋排布向四个方向延伸，几圈图标同时收拢到边缘渐近线；原先缩放 0.10 才开始淡出、0.03 才消失，这些细小图标都还画着。真机截图中最外只有一圈约 0.15–0.2 的小圆点。

改为缩放 0.24 开始淡出、0.16 以下消失（`FADE_START = 0.16`、`FADE_RANGE = 0.08`）。先试过 0.12 / 0.1，细小图标消失了，但左右边缘还剩 4 个半透明的灰影，再收紧到现值。调整后 free 模式小于 0.25 的可见图标为 4 个（无半透明残影、无小于 0.16 的图标），vertical 模式为 0；吸附、方向键、触屏拖动、两个示例逐一一致的回归通过。
